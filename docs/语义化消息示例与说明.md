# 语义化消息示例与说明

[返回 README：组件语义化](../README.md#组件语义化)

以下按组件列出本插件生成的文本，各行表示不同情况，不代表一次收到全部内容。组件描述使用 `[QQ component|…]` 包装，平台事件保留 `[QQ 平台事件|...]` 格式；示例省略防伪验证标签。关闭后“不追加语义描述”指本插件不再生成该描述，原始消息仍由 AstrBot 处理。

---

**QQ 普通表情**

开启组件语义化（依次为有名称、连击、名称未知、名称和 ID 均缺失）：

```text
[QQ component|QQ表情：微笑]
[QQ component|QQ表情：微笑，连击×3]
[QQ component|QQ表情：名称未知，ID 999，不要根据 ID 猜测含义]
[QQ component|QQ表情：名称和 ID 均未知]
```

名称可来自协议端或内置目录；连击次数大于 `1` 时追加连击说明。普通篮球表情也属于此类，显示为 `[QQ component|QQ表情：篮球]`。

**QQ 商城表情**

开启组件语义化（有名称／名称未知，分别展示未确认动画和已确认动画）：

```text
[QQ component|QQ商城表情：开心]
[QQ component|QQ商城表情：开心；动态]
[QQ component|QQ商城表情：名称未知]
[QQ component|QQ商城表情：名称未知；动态]
```

**普通图片／动图**

开启组件语义化（静态或未确认动画、已确认动画，均可附有效摘要）：

```text
[QQ component|QQ图片]
[QQ component|QQ图片：海边日落]
[QQ component|QQ动图]
[QQ component|QQ动图：海浪]
```

成功保存图片后，在同一标签中追加引用、尺寸和查看入口；群聊短期缓存额外带缓存说明：

```text
[QQ component|QQ图片；image_ref=img_a1b2c3...；1920x1080；如需查看原图，调用 qq_media(operation="inspect", params={"image_ref":"img_a1b2c3..."})]
[QQ component|QQ图片；image_ref=gimg_a1b2c3...；1920x1080；群聊短期缓存，可能过期或被淘汰；如需查看原图，调用 qq_media(operation="inspect", params={"image_ref":"gimg_a1b2c3..."})]
```

已确认动画且动画查看功能可用时，再追加 `inspect_animation` 入口；完整示例见下方“收藏／自定义表情包”。引用未保存时仅保留类型及有效摘要；引用无法可靠配对或完整标签超过长度预算时，保留独立图片引用。

关闭组件语义化：不追加图片类型、摘要或动态标记，不检测动画；成功保存引用时仍保留独立入口：

```text
[QQ ImageRef image_ref=img_a1b2c3..., 1920x1080；如需重新查看原图，调用 qq_media(operation="inspect", params={"image_ref":"img_a1b2c3..."})]
[QQ ImageRef image_ref=gimg_a1b2c3..., 1920x1080；群聊短期缓存，可能过期或被淘汰；如需查看图片，调用 qq_media(operation="inspect", params={"image_ref":"gimg_a1b2c3..."})]
```

上述引用与查看入口同样适用于可配对并保存的商城表情图片和收藏／自定义表情包；示例 ID 为占位值，实际由插件生成。

**收藏／自定义表情包**

开启组件语义化（静态或未确认动画、已确认动画，均可附有效摘要）：

```text
[QQ component|QQ表情包]
[QQ component|QQ表情包：开心]
[QQ component|QQ动态表情包]
[QQ component|QQ动态表情包：开心]
```

成功保存引用且动画查看功能可用时，例如：

```text
[QQ component|QQ动态表情包；image_ref=img_a1b2c3...；320x240；如需查看原图，调用 qq_media(operation="inspect", params={"image_ref":"img_a1b2c3..."})；如需查看动画，调用 qq_media(operation="inspect_animation", params={"image_ref":"img_a1b2c3..."})]
```

动画查看功能不可用时省略最后的动画入口；图片引用、群聊短期缓存和未保存引用的情况与普通图片相同。

关闭组件语义化：不追加表情包语义描述，不检测动画；已保存图片仍使用独立的 `QQ ImageRef`。

**语音**

开启组件语义化（当前消息或引用中的单条语音已转写成功）：

```text
[QQ component|QQ语音消息：我们下午三点见]
```

关闭组件语义化：保留转写文字：

```text
我们下午三点见
```

没有可用转写且回退识别失败时，两种模式均保留原语音组件。

**结构化卡片**

开启组件语义化，JSON 和小程序卡片有可提取字段／没有可提取字段：

```text
[QQ component|QQ JSON卡片：标题：示例卡片；提示：卡片提示；说明：卡片说明；摘要：卡片摘要；内容：卡片正文；名称：卡片名称；链接：https://example.com/card]
[QQ component|QQ JSON卡片]
[QQ component|QQ小程序卡片：标题：示例小程序；说明：小程序说明；链接：https://example.com/app]
[QQ component|QQ小程序卡片]
```

字段缺失时省略、相同内容去重；也会提取受支持的 `meta` 字段。JSON／小程序卡片最多保留八项详情，包含链接时仅保留首个去重链接；从受支持的哔哩哔哩链接中提取到 BV 号且还有空间时，追加 BV 号，例如：

```text
[QQ component|QQ JSON卡片：标题：示例视频；链接：https://www.bilibili.com/video/BV1xx411c7mD；BV号：BV1xx411c7mD]
```

XML 卡片按原文顺序提取最多四项去重内容；没有可提取内容时只标注类型：

```text
[QQ component|QQ XML卡片：示例卡片；卡片摘要；卡片说明；卡片名称]
[QQ component|QQ XML卡片]
```

无法解码的 JSON／小程序或不可解析的 XML 仍只标注对应类型。识别为红包或通过名片校验的卡片，使用对应组件的专用描述。

**红包**

开启组件语义化（钱包消息、带详情的红包卡片、无可提取详情的红包卡片）：

```text
[QQ component|QQ红包消息（仅识别，不能代领）]
[QQ component|QQ红包卡片（仅识别，不能代领）：标题：恭喜发财]
[QQ component|QQ红包卡片（仅识别，不能代领）]
```

JSON／小程序红包卡片的可选字段沿用结构化卡片规则；XML 红包卡片使用提取出的文字，例如：

```text
[QQ component|QQ红包卡片（仅识别，不能代领）：恭喜发财]
```

关闭组件语义化：若已开启 `interaction_response.respond_to_red_packet`、成功识别红包且没有其他追加文本，仍补充最小提示：

```text
[QQ component|QQ红包消息（仅识别，不能代领）]
```

关闭红包响应时不补充该提示。协议端仅上报普通文本形式的红包提示（如 SnowLuma 的 `[QQ红包]请使用新版手机QQ查收红包。`）时，按普通文字处理。

**合并转发**

开启组件语义化：

```text
[QQ component|QQ合并转发消息；res_id=abc123；如需读取正文，调用 qq_forward_get(operation="get", params={"res_id":"abc123"})]
```

缺少有效资源 ID 时只标注类型：

```text
[QQ component|QQ合并转发消息]
```

关闭组件语义化：

```text
[QQ ForwardRef res_id=abc123；如需读取正文，调用 qq_forward_get(operation="get", params={"res_id":"abc123"})]
```
