# ✨ QQ 能力增强

让 AstrBot 通过自然语言操作 QQ，也能读懂 QQ 特有的消息与互动。

`astrbot_plugin_qq_enhance` 面向 **AstrBot + OneBot v11（NapCat / SnowLuma）**，提供 **29 个模型工具、83 个操作**，覆盖消息发送、好友互动、群管理、文件处理与申请审批；同时能将表情、戳一戳、卡片和语音转写整理成模型可理解的内容。

### 🎯 插件设计理念

> [!Note]
>
> **目标：让 QQBot 真正参与 QQ 交流**
>
> 我希望这个插件不只是给 QQBot 增加一组可以调用的 API，而是让它更接近一个真正使用 QQ、理解 QQ，也能自然参与交流的人。它应该看懂表情、引用、语音、卡片和各种互动，也能发图片、回复消息、戳一戳、管理群聊，并记得对方刚才每一句话说了什么。
>
> 为此，本插件既提供各类场景的 QQ 操作，也补充各类增强能力，让模型从“能调用 QQ 接口”进一步变成“能在 QQ 中连贯地与人交流”。
>
> **为什么把增强功能放在一起**
>
> 这些功能共同参与一条完整的消息处理链路，并不是为了单纯堆叠功能。例如：
>
> - 事件消息需要在防抖内可以直接追加，避免绕过防抖机制出现顺序错乱。
> - 图片需要在当前轮保留原始视觉信息，同时避免在后续历史中长期占用大量上下文。
> - QQ 特有组件需要转换为模型可读语义，同时防止普通文字伪装成真实组件。
>
> 统一协调这些环节，才能让消息顺序、附件、撤回状态、会话归属和模型上下文保持一致，避免多个互不知情的插件分别修改同一条消息。
>
> **安全也是自然交互的一部分**
>
> 更像真人并不意味着不受约束。越丰富的 QQ 操作能力，越需要明确的安全边界。本插件同时提供：
>
> - 会话与平台隔离、调用者权限检查、敏感操作确认机制；
> - 工具按需暴露、参数与路径校验、网络访问限制；
> - 操作审计，让重要操作可确认、可追踪、可拒绝。
>
> 自然、连贯和安全不是彼此独立的附加项，而是这个插件希望一起解决的问题。

## ⚡ 快速开始

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.27,<5` |
| 平台适配器 | `aiocqhttp` |
| QQ 协议端 | NapCat `>=4.18.19` 或 SnowLuma `>=1.14.22`，使用 OneBot v11 |
| 模型 | 在 AstrBot 中配置支持工具调用的模型，并为目标会话启用模型对话 |

* 插件执行工具时会校验协议端实现与版本

* QQ 版本最好在 NapCat / SnowLuma 适配的版本范围内，否则部分接口可能失效

  > **查看版本适配**
  >
  > * [NapNeko/NapCatQQ](https://github.com/NapNeko/NapCatQQ) 切换到你使用的 NapCat 版本，其中 `packages/napcat-core/external/packet.json` 记录了具体适配的 QQ 版本
  > * [SnowLuma/SnowLuma](https://github.com/SnowLuma/SnowLuma) 为 `compat/qq.json` 记录

* 本插件开发与测试环境如下

  * Windows11
  * AstrBot 4.27.4
  * NapCat 4.18.19 / SnowLuma 1.14.22
  * NTQQ 9.9.28-46928

### 2. 安装插件

在 AstrBot WebUI 的插件管理中，使用以下仓库地址安装：

```text
https://github.com/rytte/astrbot_plugin_qq_enhance
```

也可以将完整的 `astrbot_plugin_qq_enhance` 仓库目录放入 AstrBot 的 `data/plugins/`，然后重载插件或重启 AstrBot。

初始化成功时，日志会出现：

```text
QQ Enhance initialized
```

### 3. 试着说一句

按当前会话的唤醒方式与机器人对话，例如在群聊中先 @ 机器人，再发送下面的请求。模型会根据请求选择工具，通常无需手写工具参数。

| 场景 | 示例请求 |
| --- | --- |
| 群聊或私聊 | “发一个骰子。” |
| 与机器人好友私聊 | “给我点个赞。” |
| 当前群聊 | “查看本群公告。” |
| 当前群聊 | “列出本群根目录的文件。” |
| AstrBot 管理员私聊 | “查看待处理的好友申请。” |

群管理操作还需要满足调用者和机器人自身的群权限，具体见 [权限与确认](./docs/技术原理与配置.md#permissions)。

### 4. 查看运行状态

在 AstrBot WebUI 的插件详情中打开 **“QQ 能力增强”**，可查看 OneBot 平台连接、登录账号、版本兼容性、有效配置摘要、启用能力、近期审计及待确认操作。能力列表区分配置开关与上游契约支持情况，并按平台实例列出支持状态，支持搜索和筛选。

## 💠 技术原理与配置

完整的 [💠技术原理与配置](./docs/技术原理与配置.md) 文档，包含各项功能原理、配置细节、权限与确认机制及开发参考。

以下为各项功能的精简说明，具体配置可在 AstrBot WebUI 中调整。

### 工具暴露模式

插件将 QQ 操作封装为模型工具，并按平台和启用配置决定可用范围。工具暴露模式控制每次请求向模型提供哪些工具。

| 模式 | 选择方式 | 适用场景 |
| --- | --- | --- |
| `compact`（精简） | 常用工具加上请求匹配的工具，每次最多保留 10 个 QQ 工具 | 希望进一步减少工具上下文占用 |
| `balanced`（平衡） | 在按需选择的基础上，为 AstrBot 管理员补充好友或群列表、最近联系人等工具，每次最多保留 15 个 QQ 工具 | 需要按请求补充常用能力，同时减少工具上下文占用 |
| `full`（完整，默认） | 群聊提供配置启用的全量工具；私聊保留会话与权限筛选后可见的全部工具 | 日常使用，优先保持工具列表稳定以利于提示词缓存复用 |

> [!WARNING]
>
> **模型缓存提示**
>
> 精简和平衡模式会动态改变工具列表及相关提示词，可能降低缓存命中率，工具更少不一定更省费用。完整模式在群聊中的列表更稳定，有利于缓存复用；实际效果取决于模型服务的缓存机制与完整请求前缀。

**能力包枚举值**

`toolsets.enabled_packs` 默认 `[]`，表示全部启用；也可填写以下枚举值组成的列表，例如 `["message", "group"]`。

| 枚举值 | 对应能力 |
| --- | --- |
| `status` | 登录信息、运行状态、版本等查询 |
| `account` | 修改机器人资料、头像、在线状态 |
| `friend` | 好友查询、私聊历史、点赞、戳一戳、好友管理 |
| `group` | 群信息、群成员、群聊历史、群管理、公告、精华 |
| `message` | 消息发送、合并转发、消息查询、撤回、表情回应 |
| `media` | 图片查看、动图预览、语音处理、文字识别 |
| `file` | 群文件与私聊文件操作 |
| `request` | 好友申请、入群申请和群邀请处理 |
| `web` | 网页读取、续读与页内查找 |

### 组件语义化与防伪

将 QQ 表情、卡片、语音转写等转换为模型可读文本。防伪根据真实消息结构和平台事件生成验证标签，并清理用户输入的伪造标签。

**防伪类型枚举值**

`inbound.component_spoof_protection.protected_types` 指定需要验证的组件与平台事件类型，默认值为 `["red_packet", "voice", "dice", "rps", "basketball", "poke", "notice"]`；防伪开启时不能为空。完整枚举如下：

| 枚举值 | 对应类型 | 语义化内容 |
| --- | --- | --- |
| `red_packet` | 红包消息或卡片 | 标注红包类型，仅识别，不能代领 |
| `voice` | 语音 | 语音转写文本 |
| `dice` | 骰子 | 骰子点数 |
| `rps` | 猜拳 | 布、剪刀、石头或结果未知 |
| `basketball` | 随机投篮篮球；静态篮球属于 `face` | 进球、未进球、卡篮筐或结果未知 |
| `poke` | 消息中的 QQ 互动表情；戳一戳通知属于 `notice` | 互动名称 |
| `notice` | 平台事件，包括戳一戳通知、消息撤回等 | 规范化的事件内容 |
| `face` | QQ 普通表情与超级表情 | 表情名称、连击次数 |
| `market_face` | QQ 商城表情 | 名称或摘要，识别到动画时追加动态标识 |
| `image` | 普通图片、动图、收藏或自定义表情包 | 图片或表情包类型、动态标识及有效摘要 |
| `video` | 视频 | 标注视频类型 |
| `file` | 文件 | 文件名 |
| `music` | 音乐卡片 | 标题、说明或平台与歌曲 ID |
| `contact` | 联系人名片与群名片 | QQ 号、群号及名称 |
| `location` | 位置 | 标题、说明、经纬度 |
| `share` | 链接分享 | 标题、说明、链接 |
| `json_card` | JSON 结构化卡片 | 可提取的标题、摘要、内容、链接 |
| `miniapp` | 小程序卡片 | 可提取的标题、摘要、内容、链接 |
| `xml_card` | XML 结构化卡片 | 可提取的标题、摘要、内容、链接 |
| `forward` | 合并转发 | 转发资源 ID 与按需读取入口，不附正文预览 |
| `online_file` | 在线文件或文件夹 | 类型与名称 |
| `flash_transfer` | 闪传文件 | 标注闪传文件类型 |

具体输出示例见 [语义化消息示例与说明](./docs/语义化消息示例与说明.md)。

### 其他增强能力

| 能力 | 简要说明 |
| --- | --- |
| 语音识别 | 优先使用 AstrBot 已有转写，缺失时由 QQ 协议端补充识别；支持当前及引用中的单条语音，失败时保留原语音 |
| 互动响应 | 识别红包消息后允许模型自然回复，仅识别，不能代领 |
| 平台事件处理 | 处理戳一戳、撤回、好友与群成员变化等 19 类事件，可记录为背景或主动回复；撤回会定位原会话，并与防抖协作 |
| 图片历史轻量化 | 当前轮保留视觉信息，历史使用轻量引用；群聊缓存支持先发图后提问，模型可按需回看原图或动图预览，引用按平台与会话隔离 |
| 跨会话消息衔接 | 将已发送正文和来源说明写入目标历史，方便后续交流；不会唤醒目标模型，对方实际收到的消息仅含发送正文 |
| 消息防抖 | AstrBot 本地 Agent 可结合连续输入统一回复，每条输入独立保存；已执行工具、进入流式发送或达到批次限制时，等待当前请求结束 |
| 申请通知 | 将好友申请、入群申请和群邀请投递到管理员私聊，由该会话的模型自然生成通知；通知轮不执行工具，后续审批仍受权限与确认规则约束 |
| 网页阅读 | 下载网页并在本地提取公开静态正文，无需第三方解析 API；快照按调用者与会话隔离，支持续读、查找，后两者不再联网 |

**平台事件模式**：`off` 关闭处理；`context` 写入历史作为背景，不独立唤醒模型；`respond` 记录并允许模型回复，独立事件回复不能执行工具。机器人被戳默认 `respond`，其他用户被戳及撤回默认 `context`。账号掉线仅支持 `off` / `context`，启用时需指定接收账号，将掉线事实写入其已有私聊历史。

**图片缓存与动图**：群聊缓存默认上限 256 MiB、有效期 24 小时，需开启 AstrBot 群聊上下文注入；过期或被清理的图片会明确提示不可用。GIF、WebP、APNG 动图可生成最多九帧的 3×3 九宫格及采样说明。

**红包识别差异**：NapCat 的原始钱包消息识别需在网络适配器开启 `debug`；SnowLuma 将红包作为普通文本消息，沿用普通消息的触发规则。

**网页工具**：`read_url` 读取正文并返回快照标识，`read_page_section` 继续阅读快照，`find_in_page` 按关键词查找正文。
