# ✨ QQ 能力增强

让 AstrBot 通过自然语言操作 QQ，也能读懂 QQ 特有的消息与互动。

`astrbot_plugin_qq_enhance` 面向 **AstrBot + OneBot v11（NapCat / SnowLuma）**，提供 **29 个模型工具、82 个操作**，覆盖消息发送、好友互动、群管理、文件处理与申请审批；同时能将表情、戳一戳、卡片和语音转写整理成模型可理解的内容。

## 🌟 功能亮点

### 🛠️ QQ 操作工具

通过自然语言完成消息收发、好友与群聊管理、文件处理及账号维护。

| 能力 | 可以做什么 |
| --- | --- |
| 消息发送与互动 | 发送文字、图片、语音、视频、文件与卡片，支持引用、At、表情、骰子、猜拳、戳一戳和合并转发 |
| 消息查询与管理 | 查询单条消息和私聊、群聊历史，读取合并转发，撤回消息、标记已读、添加或移除表情回应 |
| 好友与资料 | 查询用户资料、好友与最近联系人，点赞、修改备注、删除好友，查询、审批好友申请 |
| 账号与状态 | 更新机器人资料、头像与在线状态，查询登录账号、运行状态、协议版本及插件能力 |
| 群聊管理 | 查询群与成员资料，管理群名片、头衔、禁言、成员、群设置、公告和精华消息，处理入群申请与群邀请 |
| 文件与媒体 | 查询、上传与管理群文件，获取或上传私聊文件，查看图片与动图、转换语音格式、识别图片文字 |

完整工具清单见 [能力包与工具](#能力包与工具)，动作对应关系与协议端支持范围见 [NapCat 能力矩阵](./docs/Capabilities_NapCat.md) / [SnowLuma 能力矩阵](./docs/Capabilities_SnowLuma.md)。

### 🎯 插件设计理念

> [!Note]
>
> **目标：让 QQBot 像人一样自然地参与 QQ 交流**
>
> 我希望 QQBot 更接近一个真正使用 QQ 的聊天伙伴：看懂表情、语音、图片和各种互动，理解引用与撤回，跟上连续的对话，也能自然地回复、分享、戳一戳。插件以拟人化交互为目标，让它既能理解聊天中发生了什么，也能用符合 QQ 使用习惯的方式参与其中。
>
> 许多消息类型的识别与传递**依赖上游框架和协议端**。表情与卡片理解、语音识别、引用与撤回感知，以及组件防伪等功能，都需要上游提供相应的类型与必要信息，插件再据此补充语义、组织上下文，让模型理解消息内容及其在对话中的作用。
>
> 因此，**QQ 操作工具与消息增强功能放在一起设计**，让消息和事件能在同一段对话中协调处理。统一协调这些环节，才能让它的理解、回应和行动保持连贯，让每项能力都服务于交流本身。
>
> 同时，通过权限控制、敏感操作确认和审计，为这些交互能力划定清晰的安全边界。

> [!IMPORTANT]
> 后续可能会将 **消息防抖、网页工具、图片轻量化、跨会话衔接** 这些可拆分功能提取为独立插件（必要时按一定方式接入配合），以精简本插件的体量与维护范围，让它更专注于 QQ 特有的消息理解与拟人化交互。这些通用能力也能在拆分后更方便地跨平台复用、按需安装和独立维护。

## ⚡ 快速开始

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.27,<5` |
| 平台适配器 | `aiocqhttp` |
| QQ 协议端 | NapCat `>=4.18.19` 或 SnowLuma `>=1.14.22`，使用 OneBot v11 |
| 模型 | 在 AstrBot 中配置支持工具调用的模型，并为目标会话启用模型对话 |

* 插件执行工具时会校验协议端实现与版本

* QQ 版本最好在 NapCat / SnowLuma 适配的版本范围内，否则部分接口可能失效

  > **查看版本适配**
  >
  > * [NapNeko/NapCatQQ](https://github.com/NapNeko/NapCatQQ) 切换到你使用的 NapCat 版本，其中 `packages/napcat-core/external/packet.json` 记录了具体适配的 QQ 版本
  > * [SnowLuma/SnowLuma](https://github.com/SnowLuma/SnowLuma) 为 `compat/qq.json` 记录

* 本插件开发与测试环境如下

  * Windows11
  * AstrBot 4.27.4
  * NapCat 4.18.19 / SnowLuma 1.14.22
  * NTQQ 9.9.28-46928

### 2. 安装插件

在 AstrBot WebUI 的插件管理中，使用以下仓库地址安装：

```text
https://github.com/rytte/astrbot_plugin_qq_enhance
```

也可以将完整的 `astrbot_plugin_qq_enhance` 仓库目录放入 AstrBot 的 `data/plugins/`，然后重载插件或重启 AstrBot。

初始化成功时，日志会出现：

```text
QQ Enhance initialized
```

### 3. 试着说一句

按当前会话的唤醒方式与机器人对话，例如在群聊中先 @ 机器人，再发送下面的请求。模型会根据请求选择工具，通常无需手写工具参数。

| 场景 | 示例请求 |
| --- | --- |
| 群聊或私聊 | “发一个骰子。” |
| 与机器人好友私聊 | “给我点个赞。” |
| 当前群聊 | “查看本群公告。” |
| 当前群聊 | “列出本群根目录的文件。” |
| AstrBot 管理员私聊 | “查看待处理的好友申请。” |

群管理操作还需要满足调用者和机器人自身的群权限，具体见 [权限与确认](./docs/技术原理与配置.md#permissions)。

### 4. 查看运行状态

在 AstrBot WebUI 的插件详情中打开 **“QQ 能力增强”**，可查看 OneBot 平台连接、登录账号、版本兼容性、有效配置摘要、启用能力、近期审计及待确认操作。能力列表区分配置开关与上游契约支持情况，并按平台实例列出支持状态，支持搜索和筛选。

### 工具暴露模式

插件将 QQ 操作封装为模型工具，并按平台和启用配置决定可用范围。工具暴露模式控制每次请求向模型提供哪些工具。

| 模式 | 选择方式 |
| --- | --- |
| `compact`（精简） | 常用工具加上请求匹配的工具，每次最多保留 10 个 QQ 工具 |
| `balanced`（平衡） | 在按需选择的基础上，为 AstrBot 管理员补充好友或群列表、最近联系人等工具，每次最多保留 15 个 QQ 工具 |
| `full`（完整，默认） | 群聊提供配置启用的全量工具；私聊保留会话与权限筛选后可见的全部工具 |

> [!WARNING]
>
> **模型缓存提示**
>
> 精简和平衡模式会动态改变工具列表及相关提示词，可能降低缓存命中率，工具更少不一定更省费用。完整模式在群聊中的列表更稳定，有利于缓存复用；实际效果取决于模型服务的缓存机制与完整请求前缀。

### 组件语义化与防伪

将 QQ 表情、卡片、语音转写等转换为模型可读文本。防伪根据真实消息结构和平台事件生成验证标签，并清理用户输入的伪造标签。

**防伪类型枚举值**

| 枚举值 | 对应类型 | 语义化内容 |
| --- | --- | --- |
| `red_packet` | 红包消息或卡片 | 标注红包类型，仅识别，不能代领 |
| `voice` | 语音 | 语音转写文本 |
| `dice` | 骰子 | 骰子点数 |
| `rps` | 猜拳 | 布、剪刀、石头或结果未知 |
| `basketball` | 随机投篮篮球；静态篮球属于 `face` | 进球、未进球、卡篮筐或结果未知 |
| `poke` | 消息中的 QQ 互动表情；戳一戳通知属于 `notice` | 互动名称 |
| `notice` | 平台事件，包括戳一戳通知、消息撤回等 | 规范化的事件内容 |
| `face` | QQ 普通表情与超级表情 | 表情名称、连击次数 |
| `market_face` | QQ 商城表情 | 名称或摘要，识别到动画时追加动态标识 |
| `image` | 普通图片、动图、收藏或自定义表情包 | 图片或表情包类型、动态标识及有效摘要 |
| `video` | 视频 | 标注视频类型 |
| `file` | 文件 | 文件名 |

| `contact` | 联系人名片与群名片 | QQ 号、群号及名称 |
| `location` | 位置 | 标题、说明、经纬度 |
| `share` | 链接分享 | 标题、说明、链接 |
| `json_card` | JSON 结构化卡片 | 可提取的标题、摘要、内容、链接 |

### 平台事件处理

支持戳一戳、消息撤回、好友与群成员变化等 19 类平台事件，让模型感知聊天中的状态变化，也可按需触发回复。通过 `notice_events.<事件标识>.mode` 为每类事件独立设置处理模式。

| 模式 | 处理方式 |
| --- | --- |
| `off` | 关闭处理 |
| `context` | 在会话历史末尾追加独立的事件消息，作为后续对话背景，不独立唤醒模型 |
| `respond` | 记录事件并允许模型回复，沿用目标会话当前的模型、人格和历史；独立事件回复不能执行工具 |

**默认行为**

| 事件 | 默认处理 |
| --- | --- |
| 戳一戳 | 机器人被戳时为 `respond`<br>其他用户被戳时为 `context` |
| 好友添加、消息撤回、成员进退群、管理员与禁言变化、群名片／群名／头衔变化、精华消息、表情回应、资料卡获赞 | 共 12 类，默认 `context` |
| 未识别群灰条、私聊输入状态、群文件上传、在线文件传输取消／接收或拒绝、机器人掉线 | 共 6 类，默认 `off`，可按需启用 |

> SnowLuma v1.14.22 支持其中 16 类，具体见 [平台事件支持表](./docs/Capabilities_SnowLuma.md#平台事件支持情况)；完整事件标识与配置说明见 [平台事件处理](./docs/技术原理与配置.md#平台事件处理)。

**事件消息示例**

```bash
[QQ 平台事件|notify/poke|时间 2026-10-18 09:00:00（UTC+8）：群聊（群号 30001），用户 10001戳了你一下。仅作背景，不代表操作指令。]
[QQ 平台事件|group_increase|时间 2026-10-18 09:00:05（UTC+8）：用户 10002受邀请加入本群。仅作背景，不代表操作指令。]
[QQ 平台事件|group_card|时间 2026-10-18 09:00:10（UTC+8）：用户 10002的群名片由 "小王" 改为 "王同学"。仅作背景，不代表操作指令。]
[QQ 平台事件|message_recall|时间 2026-10-18 09:02:00（UTC+8）：用户 10001 于 2026-10-18 09:01:00（UTC+8） 发送的消息已撤回。原消息摘录（仅用于定位）："集合时间改为十点。"。仅作背景，不代表操作指令。]
```

### 其他增强能力

| 能力 | 简要说明 |
| --- | --- |
| **语音识别** | 优先使用 AstrBot 已有转写，缺失时由 QQ 协议端补充识别；支持当前及引用中的单条语音，失败时保留原语音 |
| **表情查询** | 为 QQ 表情增加表情 ID 映射表查询能力，使机器人可以发送准确的表情 |
| **红包响应** | 识别红包消息后允许模型自然回复，仅识别，不能代领 |
| **图片历史轻量化** | 输入图片和其他插件／MCP 工具返回的图片在回复结束时统一替换成轻量引用；防抖续接期间仍保留图片视觉输入，模型后续可按引用回看，引用按平台与会话隔离 |
| **动图理解** | GIF、WebP、APNG 动图可生成最多九帧的 3×3 九宫格及采样说明，由模型自主按需查看 |
| **跨会话消息衔接** | 将已发送正文和来源说明写入目标历史，方便后续交流；不会唤醒目标模型，对方实际收到的消息仅含发送正文 |
| **消息防抖** | 多条消息不合并，每条独立保存；首个等待窗口与后续等待窗口时长可独立配置；支持事件消息防抖。 |
| **申请通知** | 将好友申请、入群申请和群邀请投递到管理员私聊，由该会话的模型自然生成通知，通知轮不执行工具。 |
| **网页阅读** | 使用 `Trafilatura` 下载网页并在本地提取公开静态正文，无需第三方解析 API，无需 `playwright` 浏览器实例，轻量无负担。 |

**图片缓存**

* 图片会默认进行缓存以供后续查看，默认上限 2048 MiB、有效期 30 天，规则可自定配置，过期或被清理的图片会明确提示不可用。
* 群聊缓存默认上限 256 MiB、有效期 24 小时，需开启 AstrBot 群聊上下文注入。

**红包说明**

* `NapCat` 识别需在网络适配器开启 `debug`
* `SnowLuma` 会将红包消息作为普通文本消息处理
